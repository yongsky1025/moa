2. AuthUserDTO import 경로 수정 (circle·schedule 컨트롤러)

원인

세션 인증 방식에서 JWT 방식으로 전환하면서 AuthUserDTO가 users.dto 패키지에서 auth.dto 패키지로 이동했으나 컨트롤러의 import가 갱신되지 않아 컴파일 오류 발생.

수정 대상 파일 (3개)

  • circle/controller/CircleController.java
  • circle/controller/CircleMemberContoller.java
  • schedule/controller/ScheduleController.java
// 변경 전
import com.soldesk.moa.users.dto.AuthUserDTO;

// 변경 후
import com.soldesk.moa.auth.dto.AuthUserDTO;

3. CircleController - 서클 삭제·수정에 인증 추가

원인

deleteCircle, updateCircle에 @AuthenticationPrincipal이 없어 로그인한 사용자 정보를 받지 못하고 있었음. 리더 권한 검증도 없었음.

수정 내용

컨트롤러에 @AuthenticationPrincipal AuthUserDTO authUserDTO 파라미터 추가, 서비스 메서드에 userId 파라미터 추가 및 리더 여부 검증 로직 추가. 
// CircleController.java
@DeleteMapping("/{circleId}")
public ResponseEntity<Void> deleteCircle(
        @PathVariable Long circleId,
        @AuthenticationPrincipal AuthUserDTO authUserDTO) {
    circleService.deleteCircle(circleId, authUserDTO.getUserId());
    return ResponseEntity.noContent().build();
}

// CircleService.java - 리더 권한 검증 추가
public void deleteCircle(Long circleId, Long userId) {
    Circle circle = circleRepository.findById(circleId)
        .orElseThrow(() -> new IllegalArgumentException("서클이 존재하지 않습니다."));
    Users loginUser = usersRepository.findById(userId)
        .orElseThrow(() -> new IllegalArgumentException("사용자가 존재하지 않습니다."));
    circleMemberRepository
        .findByCircleAndUserAndRole(circle, loginUser, CircleRole.LEADER)
        .orElseThrow(() -> new AccessDeniedException("리더만 서클을 삭제할 수 있습니다."));
    circleMemberRepository.deleteByCircle(circle);
    circleRepository.delete(circle);
}

4. Users.java - 중복 @PrePersist 제거

원인

JPA는 한 클래스에서 같은 라이프사이클 콜백(@PrePersist)을 2개 이상 가질 수 없음. prePersist()와 addAge()에 모두 @PrePersist가 붙어 있어 앱 시작 시 PersistenceException 발생.

수정 내용

prePersist() 메서드 제거. publicId UUID 초기화 로직을 addAge()에 통합. (@PrePersist @PreUpdate 둘 다 붙어 있어 최초 저장 시에도, 업데이트 시에도 동작) 
@PrePersist
@PreUpdate
public void addAge() {
    // publicId 초기화 (최초 저장 시에만 생성)
    if (this.publicId == null) {
        this.publicId = UUID.randomUUID().toString();
    }
    if (birthDate == null) return;
    LocalDate now = LocalDate.now();
    this.age = now.getYear() - birthDate.getYear();
    if (birthDate.getDayOfYear() > now.getDayOfYear()) {
        this.age--;
    }
}

5. AdminUsersRepository - Hibernate 6 enum 타입 불일치 (주석처리)

원인

Hibernate 6는 JPQL에서 enum 비교 시 타입을 엄격하게 검사함.
u.userGender = 0 (정수와 enum 비교), u.userStatus = 'active' (소문자 문자열)는 모두 SemanticException 발생.
올바른 비교는 u.userStatus = com.soldesk.moa.users.entity.constant.UserStatus.ACTIVE 형태.

수정 내용 (팀원 코드 - 주석처리)

getCountAllAndMale(), getWithdrawnUsersCount(), getWithdrawnUsersInfo(), countWithdrawnGroupByMonth() 4개 쿼리 주석처리.
AdminService의 해당 쿼리 호출부도 0L 기본값으로 대체. 
// AdminUsersRepository.java - 주석처리된 쿼리 예시
// @Query("SELECT COUNT(u), SUM(CASE WHEN u.userGender = 0 THEN 1 ELSE 0 END) FROM Users u WHERE u.userStatus = 'active'")
// List<Object[]> getCountAllAndMale();
// → u.userGender = 0 (int vs enum 불일치), u.userStatus = 'active' (소문자 불일치)

6. AdminActionLogRepository - deleteByCreatedAtBefore (주석처리)

원인

Spring Data JPA는 메서드 이름으로 쿼리를 자동 생성함.
deleteByCreatedAtBefore는 AdminActionLog 엔티티에 createdAt 필드가 있어야 하지만, 실제 필드명은 timestamp라서 PropertyReferenceException 발생.

수정 내용 (팀원 코드 - 주석처리)

Repository 메서드와 LogCleanUpScheduler의 호출부 모두 주석처리.
나중에 수정 시: deleteByCreatedAtBefore → deleteByTimestampBefore로 변경하면 됨.

7. CustomUserDetails - @Component 제거

원인

@Component + @RequiredArgsConstructor가 함께 있어 Spring이 Bean으로 생성하려 했음.
그런데 생성자 파라미터인 Users는 @Entity 클래스라 Spring Bean이 아님.
→ NoSuchBeanDefinitionException: No qualifying bean of type 'Users' 발생.

수정 내용

@Component 주석처리. @RequiredArgsConstructor는 유지 (Lombok 생성자 필요).
이 클래스는 Spring이 자동 생성하는 게 아니라 new CustomUserDetails(user)로 직접 생성해서 사용해야 하는 클래스. 
// @Component  // Users는 @Entity라 Bean으로 주입 불가 - new CustomUserDetails(user)로 직접 생성
@RequiredArgsConstructor
public class CustomUserDetails implements UserDetails {
    private final Users user;
    ...
}

8. MoaApplicationTests - OAuth2 Mock Bean 추가

원인

SecurityConfig에서 .oauth2Login()을 사용하면 Spring이 ClientRegistrationRepository Bean을 요구함.
이 Bean은 application-oauth2.yml의 소셜 로그인 클라이언트 설정(client-id, client-secret 등)이 있어야 자동 생성됨.
테스트 환경에는 해당 파일이 없어 NoSuchBeanDefinitionException 발생.

수정 내용

@MockBean ClientRegistrationRepository 추가 → 테스트 시 가짜 Bean으로 대체.
실제 운영/개발 환경에서는 application-oauth2.yml에 아래 항목을 설정해야 함. 
# application-oauth2.yml (운영/개발 환경 필요 설정)
spring:
  security:
    oauth2:
      client:
        registration:
          google:
            client-id: YOUR_GOOGLE_CLIENT_ID
            client-secret: YOUR_GOOGLE_CLIENT_SECRET
            scope: email, profile
          naver:
            client-id: YOUR_NAVER_CLIENT_ID
            client-secret: YOUR_NAVER_CLIENT_SECRET
            ...
          kakao:
            client-id: YOUR_KAKAO_CLIENT_ID
            ...

// MoaApplicationTests.java
@SpringBootTest
class MoaApplicationTests {

    // 테스트 환경에서 OAuth2 설정 파일 없을 때 MockBean으로 대응
    @MockBean
    ClientRegistrationRepository clientRegistrationRepository;

    @Test
    void contextLoads() {}
}
