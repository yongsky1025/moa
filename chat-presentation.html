01

구현 개요 및 목표

Overview
핵심 목표 사용자 간 실시간 메시지 송수신이 가능한 채팅 시스템 구현.
1:1 채팅과 모임(그룹) 채팅 두 가지 형태를 지원하며, 메시지는 DB에 영구 저장.
구현 기능 목록
  • 1:1 채팅방 — 두 사용자 사이의 개인 채팅. 동일한 두 사람 사이에 중복 방 생성 없음
  • 모임 채팅방 — 모임(circle)별 단체 채팅. 모임당 1개 방 보장
  • 실시간 메시지 전송 — WebSocket(STOMP)으로 즉시 브로드캐스트
  • 메시지 내역 조회 — 페이징 처리(최신순), 입장 시 이전 대화 불러오기
  • 안읽은 메시지 수 — 마지막 읽은 시각 기준으로 카운트
  • 읽음 처리 — 채팅방 입장 시 자동 읽음 처리
사용자 시나리오

1:1 채팅 흐름

  • 채팅 버튼 클릭 → 방 자동 생성
  • WebSocket 연결 및 방 구독
  • 메시지 입력 → 상대방 즉시 수신
  • DB에 메시지 영구 저장

모임 채팅 흐름

  • 모임 가입 시 채팅방 자동 연결
  • 모임원 전체에게 메시지 브로드캐스트
  • 이전 대화 내역 페이징 조회
  • 알림 배지로 안읽은 수 표시

WebSocket vs HTTP 비교
항목HTTP (REST)WebSocket (STOMP)
연결 방식요청-응답 (단방향)지속 연결 (양방향)
실시간성폴링 필요 (지연 발생)즉시 전달 (지연 없음)
서버 부하반복 요청으로 높음연결 유지로 효율적
채팅 적합성부적합최적
STOMP 프로토콜을 선택한 이유 순수 WebSocket은 메시지 라우팅 기능이 없어 채팅방별 구독 관리가 어렵습니다. STOMP는 /topic/room/{roomId} 형태의 목적지 기반 라우팅을 제공해 채팅방 분리가 간단하고, Spring에서 공식 지원하므로 코드가 단순해집니다.

DB 테이블 구조

chat_room

  • id (PK)
  • room_type (DIRECT/GROUP)
  • direct_key (1:1 중복 방지 키)
  • circle_id (모임 채팅 전용)
  • created_at

chat_room_member

  • id (PK)
  • room_id / user_id (UK)
  • joined_at
  • last_read_at (읽음 처리 기준)

chat_message

  • id (PK)
  • room_id (인덱스)
  • sender_id
  • content (최대 1000자)
  • created_at (인덱스)
